## The principle (why this exists)

**The action language's boundary = the body's degrees of freedom (3 position +
3 orientation + gripper), NOT the task list.** The language is written ONCE
over the body and never grows with tasks. A new skill is not a new token — it
is a new *trajectory* the brain discovers inside this fixed space. Any DoF
confiscated by the harness is a DoF the teacher can never learn to use ("what
orientation suits what situation"). This is the direct corollary of the
founding-intent commitment (conditional knowledge must be earned) and the
reason the PI vetoed fixing the vertical orientation DoF for pushing.

## Three constitutional constraints (every action-language choice must satisfy)

1. **Visually reasoned** — the VLM must be able to infer the action from the
   image. ("Press down 60°" is inferable; `[-0.217,-0.658,0.226,-0.685]` is
   not → quaternions are banned from the model layer.)
2. **Discrete-token verifiable** — actions are integer tokens generated by
   constrained decoding (classification, not regression), so they can be
   format-contract checked.
3. **Shares the text space with memory** — the action vocabulary lives in the
   same textual space as recap/memory (P1's existence condition, P2
   r-tracking's interpretability). Joint-space would destroy this.

## A-spec v2-final — model-layer action language (per round, left arm)

```
LEFT_TARGET_POS: X=<int> Y=<int> Z=<int>      REQUIRED. integer cm, base frame
                                               (same canonical as L0a).
LEFT_TARGET_ORI: P=<int> Y=<int> R=<int>      OPTIONAL. integer degrees, OFFSET
                                               from the neutral contact
                                               orientation:
                                                 P = pitch (about the motion
                                                     frame's lateral axis;
                                                     + = fingertip presses down)
                                                 Y = yaw   (about the vertical)
                                                 R = roll  (about the motion axis)
                                               omitted → neutral orientation.
GRIP: OPEN|CLOSE                               body DoF, language reserved slot.
                                               The push task's affordance
                                               contract LOCKS it to CLOSE — not
                                               an addition, an activation.
```
- **Force / wrench**: NOT in the token space; the executor's stiffness profile
  manages it; it enters the language only when the hardware/interface is made
  honest (P4).
- **Examples:** palm push = omit ORI; fingertip push = `LEFT_TARGET_ORI: 60,0,0`.

## Representation choice: semantic Euler OFFSET, integer degrees

Three exclusions, each with its reason:

- **6D rotation (Zhou et al. 2019) — EXCLUDED here, deferred to P4.** Zhou's
  theorem is about a neural *regression head* outputting SO(3): any ≤4-D
  representation is discontinuous and hurts gradients. Our teacher/student
  generate integer tokens via constrained decoding = *classification*, not
  regression — Zhou's premise does not hold (RT-1/RT-2's binned Euler is the
  precedent). 6D is filed to **P4 "learned action decoder"** — when there is a
  regression head, revisit then.
- **Quaternion — BANNED from the model layer.** It is the executor's internal
  pipeline language (the OSC API consumes it); the model never emits it. A VLM
  can reason "press down 60°" from the image; it cannot reason
  `[-0.217,-0.658,0.226,-0.685]`.
- **Joint space (π0 style) — EXCLUDED, Ledger P4 item.** π0's "learnable
  orientation" comes from demonstration data + a continuous regression head,
  NOT from joint space itself. We are zero-demo, our frozen prompted teacher
  cannot emit joint streams, and joint space destroys the shared action↔memory
  text space (constraint 3).

## Neutral contact orientation (primitive-owned; the DEFAULT when ORI omitted,
## NOT a confiscation)

Computed from the current motion direction: the contact-face normal aligns to
the motion direction, the palm face lies flat on the table; Pin-7a orientation
as the null basis, rotated about the vertical to align with the push heading.
This is geometry that is **deterministically computable given the motion
direction** — same family as IK, not a decision → it belongs to the primitive.
The teacher may OVERRIDE it any round via `LEFT_TARGET_ORI`.

**Gauge vs decision criterion (filed):** the choice among *equivalent*
orientations = gauge (0 bits) → primitive. An orientation that *changes the
outcome* with the situation = a decision → teacher. (This is exactly why
"palm-push vs fingertip-push produce different results" MUST be a token: it is
outcome-changing, hence a decision.)

## Executor (two safeties)

- **neutral ∘ offset** (z-y-x order, applied in the neutral frame) → quaternion
  → OSC. Interpolate in **quaternion space (slerp)**: Euler's gimbal concern
  exists only in the interpolation/regression domain; the executor's internal
  quat interpolation dissolves it.
- **Soft orientation stiffness** (~1/5 of position stiffness) + joint-limit-
  aware clamp: a bad angle is gently guided, does not hit the table or jam.
