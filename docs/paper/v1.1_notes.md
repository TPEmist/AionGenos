## FINDING (holds regardless of L2's fate) — memory needs a success floor

L2 collect gave teacher SR = 1/100; the recap buffer is 1 desirable +
99 undesirable. Stated as a finding, not a mishap:

**Memory can only supply *conditional* knowledge if there exist success
experiences to condition on. A retrieval buffer built from a
near-failing teacher retrieves "others also failed here" — it cannot
supply the situation→correct-correction map that is the whole value of
memory (§4.3).** This is the cold-start / minimum-initial-competence
threshold (cf. SimpleVLA-RL's RL cold-start) reappearing on the *memory*
side: below a task-competence floor, externalising memory has nothing to
externalise — the same "minimum viable competence" law seen from the
memory face rather than the RL face.

One paragraph in Discussion (future work / scope): the marginal/
conditional criterion presupposes the teacher clears a task-competence
floor; L2 dual-push at 1% SR sits below it, which is itself evidence for
the floor and a boundary condition on "distil the competence,
externalise the memory" — you cannot externalise a competence the
teacher does not have.

## LESSON (2026-07-28) — the shared working tree was the third un-isolated resource

GPU contention was closed with a lockfile; session territory (isaac = L2
pipeline/eval, paper = v1.1 writing) was drawn conceptually. But both
sessions still shared ONE working tree (`/home/control/AionGenos`), and a
branch does not isolate a working tree — a `git worktree` does. The
symptom: the L2 GGUF-export fix (`ae75ada`) was committed onto
`paper-v1.1-wip` instead of master, because the tree was left on the paper
branch. **A shared working tree is the third un-isolated shared resource,
alongside the GPU and the pipeline owner; now closed with a worktree**
(`/home/control/AionGenos-paper`). Rule: paper writing happens only in the
paper worktree, `docs/paper/` only; master is isaac's. (Untangle recorded
in `docs/handoff/2026-07-28_paper-isaac-worktree-split.md` on master.)

## LESSON (2026-07-29) — when you find one stray, ask its generating mechanism how many it produced

The 2026-07-28 untangle cherry-picked the ONE visible stray L2 commit
(`ae75ada`) to master and declared the collision closed. A later
close-out audit (reflog → `git log <old-paper-tip>..`, patch-id + content
check) showed the shared-working-tree window had produced **four** stray
L2 commits, not one: `ae75ada` (GGUF fix, re-homed `154e974`), `6cf31b7`
(Amendment 3 doc, re-homed `5447112`), **`eb93ebb`** (per-arm eval CODE +
format-contract gate — NOT on master), **`9c2568a`** (frozen-buffer SHA
pin — NOT on master). Two were still un-homed, one of them the eval code
that the master confirmatory report depends on for reproducibility.

**Rule:** a stray commit is a *symptom of a window*, not an isolated
event. The moment `ae75ada` was found on the wrong branch, the correct
next step was to scan the ENTIRE divergent range for every commit the same
shared-tree window generated — not to fix the one in hand and move on.
Close-out = "all commits from the window are accounted for (re-homed or
confirmed-intended)", not "the known ones are patched". The one-command
audit (reflog + range log + per-commit re-home check) is the closer;
run it whenever a territory/isolation breach is discovered.

*(The two un-homed strays `eb93ebb`/`9c2568a` are L2-pipeline = master =
isaac territory; routed to isaac, not fixed by the paper session. Push

call; master pushed by isaac after it closes the reproducibility gap.)*
