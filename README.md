# AionGenos

Code, pre-registration and analysis record for the paper

> **Externalise the Memory: A Pre-Registered Study of Where an Embodied Agent's Experience Should Live**
> arXiv:[ID]

Should an embodied agent's accumulated experience be baked into its policy
weights, or kept external and retrieved at inference? A memory-augmented
teacher (a VLM that retrieves lessons, with their episode images, from its own
past attempts) produces trajectories on a vision-conditioned single-arm reach
task in Isaac Lab. From the same trajectories we distil LoRA student policies
and evaluate them under matched protocols, including one that re-attaches the
teacher's frozen retrieval buffer to a fixed set of student weights. The
hypotheses, arms, tests and analysis rules were pre-registered before training
and before any p-value. Distilling the memory-augmented behaviour into weights
did not detectably help, so the memory-in-weights claim is **withdrawn, not
refuted**. Attaching retrieval to fixed student weights did help, by a large
margin. The recipe that follows is to externalise the memory.

## Headline results

Single-arm reach task, n = 100 episodes per arm. Success counts are as run; the pre-registered auto-reset sensitivity count (Amendment 15 pin 8) is given beside them. "Confirmatory" and
"exploratory" are as tagged against the registered plan.

| Result | Number | Status |
|---|---|---|
| T1: memory-distilled student vs action-only control | +1 pp (n.s.) | confirmatory; underpowered for its own minimum effect, so the memory-in-weights claim is withdrawn |
| Identical-weights contrast: same adapter, retrieval attached vs bare | +34 pp, z = 5.15 | exploratory (not a registered primary test) |
| T4: protocol contrast, retrieval arm vs memory-distilled arm | +23 pp, z = 3.36 | confirmatory |
| Pooled memory-augmented teacher reference | 49.3% (sensitivity 47.5%) | reference (three unseeded collect runs, not seed-matched to the evaluation); the retrieval arm reaches it |
| Amendment 15: frozen buffer on the base model, no adapter | 48 vs 49 of 100 (retrieval arm); sensitivity 48 vs 48 | registered after the main results, before any of its episodes ran |
| Amendment 15: frozen buffer on the other three adapters | 53 / 53 / 55 of 100 (from 25 / 26 / 19 without it); sensitivity 53 / 50 / 55 (from 21 / 19 / 17) | registered after the main results, before any of its episodes ran |
| Second, harder task (L2), identical-weights contrast | +6 pp (n.s.) | confirmatory contrast on a per-arm success metric promoted post hoc; below the minimum detectable effect; direction-consistent, not a replication |

What the paper does and does not claim:

- **Memory in weights: withdrawn.** The T1 null is scoped to this recipe
  (single-round SFT + composable KTO), this task, this data scale and this
  adapter capacity (LoRA rank 16). It is not a refutation.
- **"Distil the competence": withdrawn.** With the buffer attached, success is
  48 to 55 of 100 whatever weights are loaded, including no adapter at all. The
  retrieval effect does not depend on the adapter, and the adapter adds nothing
  detectable once the buffer is attached.
- **No inference-cost or latency advantage.** Teacher and student share the
  same 31B base and both generate a rationale before the action. Per-step cost
  is of the same order for teacher, student and student + retrieval.
- **Mechanism: exploratory.** A behavioural probe with pre-registered per-arm
  predictions is consistent with distillation transferring the *marginal*
  correction (a static prior every arm adopts) but not the *conditional*,
  situation-specific correction that retrieved memory supplies.
- **L2: exploratory diagnostics only.** They tie the weaker effect to memory
  coverage and a distance-gated conversion threshold.

## Setup

- **Simulator.** Isaac Lab, with an OpenArm bimanual reach task. The right arm
  is held frozen, so the task is single-arm.
- **Models.** Gemma-4-31B-it (multimodal, GGUF, 4-bit) is the base for both
  teacher and student. The students are LoRA adapters (single-round SFT +
  composable KTO).
- **Serving.** A GPU host serving llama.cpp `llama-server`. The teacher
  endpoint and the student endpoint (base + LoRA) are separate. Set
  `TEACHER_URL` and `STUDENT_URL` to point at your own server; the defaults in
  `aiongenos/config.py` are site-specific.
- **Memory.** Each episode yields a recap: a short, observable-only visual
  lesson. It is stored with a 768-d DINOv2 image embedding and a state anchor,
  then retrieved top-K into the prompt with its initial episode image.

## Install

```bash
pip install -e ".[dev]"
pytest tests/
```

The `tests/test_aiongenos_env*.py` tests, and all simulator scripts, need an
Isaac Lab installation. Launch the scripts through Isaac Lab, for example
`<isaaclab>/isaaclab.sh -p scripts/run_collect.py ... --headless --enable_cameras`.
They also need a reachable llama.cpp server.

## Reproduce

[`docs/paper/REPRODUCE.md`](docs/paper/REPRODUCE.md) re-runs the two
100-episode evaluations behind the identical-weights contrast: the
`A_ctrl_rat` adapter bare, and the same adapter with the frozen retrieval
buffer attached (`C_retrieval`). The guide covers:

- the exact code commit, Isaac Lab commit, base-model files and server script;
- SHA-256 hashes of the adapters and of the frozen-buffer release pack;
- the commands and flags (episode *k* uses seed 4500 + *k* in both runs);
- the 95% Wilson intervals that a re-run should be compared against.

The adapters and the frozen retrieval buffer are distributed as assets of the
GitHub Release tagged **`paper-v1-artifacts`** in this repository, published
on the arXiv upload day. Raw replays are not released.

## Pre-registration and amendment chain

The study was registered in two locked layers. The hypotheses, arms, primary
tests and directionality were fixed before any adapter trained. The final
analysis rules were fixed after collection but before any p-value was
computed.

- **D11 (main task):** [`docs/d11_preregistration.md`](docs/d11_preregistration.md).
  The amendment log (§12) is in the same file, newest first. Notable entries:
  - Amendment 14 is the analysis-time decision lock: the pairing-integrity
    gate, the mechanical test-selection fallback, the scoping of the withdrawn
    T1, and the exploratory analyses.
  - Amendment 15 covers the adapter controls (base + buffer; buffer on the
    other adapters), the R1' slope probe and a descriptive same-hardware cost
    re-measure. It was registered after the D11 results and before any of
    its own numbers existed. Its sub-amendment A15.1 re-set the slope probe's
    recovery gate (1 mm to 15 mm) after the pinned gate failed on instrument
    grounds; the D11-arm slopes are therefore post hoc.
  - Amendment 16 is a documentation-only units erratum.
  - Supporting audits are in [`docs/d11_preregistration/`](docs/d11_preregistration/).
- **L2 (second task):** [`docs/paper/l2_prereg.md`](docs/paper/l2_prereg.md), then
  [`l2_amendment_1.md`](docs/paper/l2_amendment_1.md),
  [`l2_amendment_2.md`](docs/paper/l2_amendment_2.md) and
  [`l2_amendment_3.md`](docs/paper/l2_amendment_3.md). Each is marked
  LOCKED before the results it governs. The confirmatory output is in
  [`docs/paper/l2_confirmatory_report.md`](docs/paper/l2_confirmatory_report.md).

Every result in the paper is tagged confirmatory or exploratory against this
registered plan.
